# Document System Restructure Product Spec

状态：进行中
最后更新：2026-04-20
范围：`docs/` 新文档管理体系的产品定义

## 1. 目标

- 让使用者能快速分辨当前生效文档、过程文档和历史文档
- 让每一轮功能/重构或 hotfix 都有明确落盘位置
- 降低顶层 `docs/` 的认知负担，避免角色混写

## 2. 范围

In scope：

- 收敛当前生效文档集合
- 引入 `backlog/` 和 `hotfix/` 的正式治理
- 用新的顶层文档承接旧文档中的重要内容

Out of scope：

- 重新设计所有历史归档机制
- 对每一份历史过程文档做细粒度重写
- 借本轮重构再次发明新的文档分类层级

## 3. 验收标准

- `README.md` 只承担文档治理入口职责
- 顶层当前生效文档集合明确，且互不串味
- 旧顶层文档不再和新顶层文档并列为“当前事实”
- `architecture.md` 能准确解释当前代码里的真实层次

## 4. 量化与观测

- 顶层当前文档数显著收敛
- `README.md` 中不再出现未达成共识的结构
- `AGENTS.md` 的参考文档列表与当前顶层文档集合一致
